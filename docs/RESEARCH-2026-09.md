# rGi research review: grounded adaptation

Reviewed 8 September 2026. Scope: eight primary research sources relevant to a perpetual runtime. This is a bounded review, not an exhaustive ranking of frontier systems. Paper results below belong to their authors; none are reproduced by rGi.

The practical objective is measurable transfer and retained improvement under fixed compute and permissions. Persistence, concurrent agents, generated code volume and runtime throughput do not establish general intelligence.

Authors report ALFWorld 69.3% versus ReAct 64.6%, but concrete workflow induction leads on other tasks. | Evaluate candidate and baseline on identical heldout cases. ## What this release adapts

The implementation combines three engineering mechanisms: bounded durable outcomes available to subsequent planning alongside freshness filtered observations; bounded beam search over an injected transition model; and paired heldout candidate evaluation with disjoint manifests and statistical correction. These are engineering adaptations motivated by the research, not paper reproductions. Historical outcomes retain timestamps but are not automatically expired; the planner must assess their current applicability.

Memory changes context. Predictive search changes action selection. Neither changes foundation model weights. The existing small online dynamics learner can adapt a scalar parameter, which is materially narrower than continuous multimodal plasticity or structural model evolution.

Maintain a hard boundary between observed outcomes and imagined transitions. Record failures as well as successes; otherwise the runtime learns from a biased success archive. A failed process restart must not turn an unresolved external action into an observed success. Model reported confidence is a score until calibrated against real outcomes.

## Evaluation and release discipline

1. Compare identical tasks, seeds, budgets and permissions. Report baseline and candidate costs, elapsed time, completed outcomes and human intervention.
2. Separate development, selection and final test manifests. Disjoint identifiers are a useful integrity check but do not prove semantic independence; an operator must prevent copied or near duplicate tasks.
3. Use paired outcomes because the same task is run by both candidates. Correct for the declared number of comparisons. Report effect size alongside significance and reject malformed, incomplete or contradictory evidence.
4. Preserve a retention suite and test stale observations, missing sensors, wrong predictions, restart and stop. A global mean can hide an unacceptable domain regression.
5. Rotate selection data across generations and reserve a sealed final test set that is never used to choose candidates. Statistical correction within one batch does not control an unlimited sequence of adaptive comparisons.

Local simulations test mechanics and known invariants. They do not establish broad transfer, commercial reliability or SOTA performance. Production capability claims require independent tasks and real provider/hardware measurements. The next costly experiment should be chosen only after comparing the added model calls against the improvement in accepted customer outcomes.

Acceptance: a reviewer can replay the same evaluation manifest and decision, confirm that stale observations are excluded, and observe that prediction failures or a rejected candidate cannot bypass execution policy.
