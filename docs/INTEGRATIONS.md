## Host integration

Instantiate `AgenticowExecutor` with an existing isolated `AgenticMemory` branch. The host owns filesystem policy and holds the base-memory handle; agent payloads cannot choose a path or promote a branch.

AgenticOW forwards only explicit vector/id/text fields, not arbitrary metadata. Text is still potentially sensitive: the host must approve its classification and retention policy before authorizing `memory.ingest`, isolate tenant branches, and avoid logging raw content. This adapter does not perform DLP or establish that memory is appropriate to share. Embeddings can also disclose sensitive information.

Instantiate `MetaHarnessExecutor` with trusted SDK `ToolDef` objects, one explicit capability per registration, a payload validator, and a cost ceiling. Only register read-only or independently idempotent handlers. The upstream handler contract does not accept an AbortSignal or idempotency key. The wrapper checks cancellation before dispatch, but cannot revoke an in-flight side effect. A fixed `costMicros` is an explicit charge/ceiling, not provider usage telemetry; the host must reconcile externally billed costs.

For Autogenous, bind its `admitObservation` function to `fromRuField`. The wrapper additionally rejects future and expired observations; its clock rule is stricter than upstream's default five-second future skew. Admission does not grant action authority. The full upstream observation is nested in rGi `data`, including derived lineage, so a recalled belief is not silently laundered into independent sensing evidence.

For rvCSI, inject an already opened `RvcsiRuntime`. The native method serializes Rust enums as PascalCase (`MotionDetected`), not the separate logging slug (`motion_detected`). `timestamp_ns` is a u64: ordinary JSON.parse would round contemporary nanosecond timestamps, so the adapter uses Node24 reviver source context and preserves unsafe integers as decimal strings. A host function maps nanoseconds to runtime milliseconds because device time must not be assumed to be UTC. `calibration_version: null` is legal upstream and stays unknown; CSI events do not silently acquire RuField privacy/expiry fields. A drain consumes upstream events even if subsequent validation fails; production hosts should retain capture/replay data for recovery.

## Verification

Both sensor mappings call the runtime's `validateObservation` before returning and enforce its default 65,536-byte record limit. Deployments with a smaller configured limit must additionally validate against that limit. rvCSI source identifiers are stable `rvcsi:<sha256>` names; raw names remain in `data.source_id`. Composite event IDs stay within 128 ASCII characters even with maximum u64 identifiers. RuField caller IDs and source IDs must already satisfy the runtime's 128-character ASCII identifier contract; invalid names are explicitly rejected. The integration test passes punctuation-bearing CSI names through an actual in-memory Runtime.observe call and verifies RuField rejection semantics. CSI drain consumes events before mapping errors, including oversized-record rejection; retain capture data to replay failures.

Run `node --test tests/adapters.test.ts` with Node 24. Fixtures assert exact method arguments, malformed vector rejection, bounded result counts, unknown capability rejection, schema checks, cost reservation, cancellation before dispatch, and preservation of observation metadata. This is fixture validation, not an upstream installation test.
